# Подтверждение почты при регистрации

Новая публичная регистрация сохраняет аккаунт в состоянии ожидания подтверждения.
Сеанс входа не создаётся, учебные и платёжные API недоступны. Сервис отправляет
служебное письмо со ссылкой на `https://app.adym.ru/#verify=...`.
Ссылка действует 24 часа, токен хранится только как SHA-256 хеш и отсутствует в HTTP-журналах.
При открытии ссылка удаляется из адресной строки; GET ничего не подтверждает.
Для завершения нужен также пароль регистрации: это препятствует случайной активации
чужой регистрации с паролем злоумышленника. После подтверждения пользователь входит обычным способом.

Кнопка «Не пришло письмо подтверждения?» повторяет отправку не чаще раза в минуту,
до пяти раз в час на аккаунт. Новый запрос аннулирует предыдущую ссылку. Есть лимит по IP
и ограничение параллельных отправок. Для неизвестной, уже подтверждённой или заблокированной
почты используется одинаковый ответ без письма. Ошибка SMTP при первоначальной регистрации
показывается пользователю, вход остаётся закрыт, доступен повторный запрос.

Восстановление пароля тоже доказывает владение почтой: пользователь задаёт собственный пароль,
потерянные ссылки подтверждения аннулируются, вход становится доступен.
Устройство резервируется только после подтверждения, чтобы ошибочная почта не блокировала регистрацию.
Если подтверждение проходит через восстановление пароля, резервируется текущее устройство
владельца почты. Этот путь также соблюдает ограничение регистрации на одном устройстве.

Существующие до обновления аккаунты сохраняют доступ. Они не получают ложной отметки
«почта подтверждена»: `email_verified_at` остаётся пустым до доказательства владения почтой.
В административной выгрузке доступны `email_verified_at` и `email_verification_required`;
токены и хеш устройства туда не включены. При удалении аккаунта связанные токены удаляются.

Почтовые настройки общие с восстановлением пароля: [PASSWORD_RECOVERY.md](PASSWORD_RECOVERY.md).
Вложения, пароли пользователей и полные письма в базе не сохраняются.

## Доставляемость (26 октября 2026)

Действующая DNS-зона adym.ru находится в панели `server27.hosting.reg.ru`, а почта
support@adym.ru отправляется с `sm40.hosting.reg.ru` (31.31.197.79). Записи только
в панели sm40 не заменяют записи действующей зоны. В рабочей зоне SPF дополнен
`ip4:31.31.197.79`, а TXT `dkim._domainkey` содержит публичный ключ именно sm40.
Gmail до исправления возвращал 550-5.7.26: не прошли SPF и DKIM.
При смене почтового сервера нужно синхронизировать эти записи в действующей зоне.
Принятие SMTP-сервером не доказывает доставку: проверять возвраты и получение у адресата.
