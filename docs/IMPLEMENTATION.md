# Решение и пошаговый план

## 1. Голова — первый приоритет

Выбран лёгкий гибрид: сетка лица MediaPipe + подогнанная процедурная голова. Оболочка начинается точно на 36 вершинах овала лица; следующие кольца расширяют виски и уходят к затылку. Уши имеют углубление раковины и выступ ободка. Шея состоит из эллиптических колец. Волосы — отдельная сетка скальпа с небольшим рельефом прядей.

Материал лица больше не отключает проверку глубины. Это исправляет прежнее наложение лица поверх головы. Центр вращения перенесён внутрь головы.

```js
import {skullGeometry, earGeometry, neckGeometry, hairGeometry} from './head-geometry.mjs';
const head = skullGeometry(facePositions);
const leftEar = earGeometry(head, -1);
const rightEar = earGeometry(head, 1);
const neck = neckGeometry(head);
const hair = hairGeometry(head, 'short');
// positions/indices передаются в Three.BufferGeometry.
```

| Подход | Использование | Ограничения |
|---|---|---|
| MediaPipe + процедурные части | Реализованная базовая версия | Уши и волосы приблизительные |
| Готовая голова с ригом и blendshapes | Рекомендуемый следующий шаг | Нужна лицензированная модель, UV и подгонка; наклейка фото не даст сходства |
| Упрощённая голова по точкам | Основа текущего гибрида | RGB-камера даёт относительную, а не метрическую глубину |
| Фотограмметрия | Дополнительный серверный режим | Три фото недостаточны для надёжного результата; нужны много кадров, неподвижность и ровный свет; волосы проблемны |

Следующий шаг качества: лицензированная GLB-голова с ушами, шеей, глазами, зубами и blendshapes. Подгонять лицо по точкам и профилям, переносить фото в её UV с масками видимости и смешиванием швов. Для точного скана добавить видео вокруг неподвижного родителя, серверную реконструкцию и облегчение результата для телефона. Текущие боковые фото уточняют цвета, а не восстанавливают точную геометрию затылка.

## 2. Голосовой вопрос — реализовано

`web/app.js::voiceQuestion` записывает моно через AudioWorklet по кнопке, ограничивает вопрос 25 секундами и освобождает микрофон до облачного запроса.

```python
from speech import SpeechRecognizer
recognizer = SpeechRecognizer(api_key)
text = recognizer.recognize(wav_bytes)
```

`speech.py` проверяет WAV, уровень и длину, преобразует 8–96 кГц в 16 кГц и отправляет raw LPCM в SpeechKit v1. Лимит API — 30 секунд и 1 МБ; приложение оставляет запас. Ключ находится только в Python.

Для непрерывного диалога следующий шаг — streaming STT, VAD и отдельное включение постоянного микрофона. Сейчас «помоги» может быть частью записанного вопроса; фонового wake word нет.

## 3. Подсказки — реализовано

`dialogue.py` хранит историю и этап в памяти сервера. Клиент передаёт вопрос, уровень и ID диалога. Попытки 0–2 получают инструкцию дать маленькую подсказку и вопрос без итогового ответа. С попытки 3 допускается полное решение. Ошибка или отмена до получения текста не увеличивает этап. «Новое задание» сбрасывает его.

```python
reply = tutor.answer(question, history, level, attempt=attempt)
# этапы 1–3: одна подсказка + наводящий вопрос;
# этап 4+: полное объяснение допустимо;
# правильная попытка: проверка и похвала конкретного шага.
```

Следующий шаг: структурированные ответы (`hint`, `question`, `correct`, `solution`) и проверка учебных сценариев. Пока соблюдение запрета готового ответа зависит от YandexGPT; модель может ошибиться.

## 4. Озвучивание и губы — базовая связка реализована

POST `/api/dialog` возвращает ID задания. GET `/api/dialog/<id>` сообщает `thinking`, `speaking`, `done`, `error` или `cancelled`, текст и `cues`. WAV доступен через защищённый `/api/dialog-audio/<id>`. POST `/api/dialog-cancel` останавливает синтез. Если XTTS недоступен, текст сохраняется с объяснением ошибки.

```python
# voice_worker.py — отдельный процесс:
tts.tts_to_file(text=reply, speaker_wav=str(reference), language='ru',
                file_path=str(bank / 'phrase-0.wav'), split_sentences=True)
# lipsync.py:
cues = timeline(bank / 'phrase-0.wav', reply)
# {time: секунды, open: 0..1, shape: 'round'/'closed'/...}
```

Окна аудио — 40 мс; паузы исключаются из распределения букв. Б/П/М смыкают губы, О/У/Ё/Ю округляют, И/Ы/Е/Й растягивают. Амплитуда управляет челюстью. Ф/В помечаются как `teeth`, но без отдельной модели зубов пока используют нейтральную ширину. Движения сглаживаются и привязаны к Web Audio clock. Напоминания используют только амплитуду.

Для качественного русского lip-sync следующий шаг — фонемизация текста, принудительное выравнивание с WAV на сервере и полноценные blendshapes GLB. Текущий алгоритм не даёт точного совпадения каждого звука.

## 5. Анимация и телефон

Реализованы повороты, наклоны, лёгкие речевые кивки, моргание и `prefers-reduced-motion` для головы. Напоминания не перекрывают вопросы и речь. Рендер ограничен 30 кадрами/сек.

Дальнейшие этапы: реакции на возвращение ребёнка и успех, раздельное вращение головы/шеи, риг глаз и случайные моргания. Затем мобильный клиент: камера/MediaPipe/Three.js на телефоне, Yandex и XTTS на защищённом сервере. Не открывать текущий localhost-сервер в интернет без HTTPS, авторизации, лимитов и разделения профилей. Мобильная упаковка пока не реализована.
