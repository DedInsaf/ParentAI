# Решение и пошаговый план

## 1. Автоматический сканер → настоящая модель

Ручной редактор точек и процедурная оболочка удалены из активного `app.js`. Создание идёт через встроенный Avaturn SDK 1.1.0. Нужен собственный проект с T2 в `PARENTAI_AVATURN_SUBDOMAIN`; в отсутствие конфигурации запуск блокируется с понятным объяснением. `demo` не используется для родителей. Снимки передаются Avaturn после явного согласия, не через сервер ParentAI.

```javascript
const scanner = await scannerSDK(container, configuredUrl, async result => {
  const bytes = await readExport(result, configuredUrl, abort.signal);
  const model = await ModelAvatar.create(THREE, bytes);
  await api('avatar-model', bytes); // сервер проверяет и сохраняет приватно
  installModel(model);
});
```

`avatar-scanner.mjs` проверяет origin/source сообщений SDK и признак анимируемого экспорта. Принимаются встроенные данные или HTTPS с домена проекта / assets.avaturn.me. Отмена удаляет iframe и слушатели, обрывает получение файла. Истечение 45 секунд при загрузке сканера либо 120 секунд при экспорте показывает ошибку.

`avatar_model.py` проверяет контейнер, встроенные текстуры, размеры геометрии, иерархию, суставы Head/Neck и формы jawOpen/eyeBlinkLeft/eyeBlinkRight. T1 без анимации не подменяет профиль. Модель сначала сохраняется под уникальным именем, затем профиль v6 заменяется атомарно. `/api/avatar-model` GET/POST требует токен; POST дополнительно проверяет Origin. `data/` не служит публичной папкой.

`ModelAvatar` использует GLTFLoader, исходные пропорции скелета и встроенные формы лица. Камера показывает голову, шею, плечи и верх одежды. Движение происходит через суставы и morph targets; UV и фотография для поворота не деформируются. Контур шеи самостоятельно не достраивается. Полученные тело, одежда и причёска — варианты Avaturn, а не точная реконструкция настоящих плеч и футболки. T2 жертвует частью сходства ради анимации.

Реальная генерация ещё требует подключения проекта и проверки личного скана. Старые профили сохранены, но старый условный аватар больше не загружается. Мобильный сценарий требует отдельного HTTPS-сервера с авторизацией и разделением пользователей; текущий loopback-сервер не развёрнут в интернете.

## 2. Голосовой вопрос — реализовано

`web/app.js::voiceQuestion` записывает моно через AudioWorklet по кнопке, ограничивает вопрос 25 секундами и освобождает микрофон до облачного запроса.

```python
from speech import SpeechRecognizer
recognizer = SpeechRecognizer(api_key)
text = recognizer.recognize(wav_bytes)
```

`speech.py` проверяет WAV, уровень и длину, преобразует 8–96 кГц в 16 кГц и отправляет raw LPCM в SpeechKit v1. Лимит API — 30 секунд и 1 МБ; приложение оставляет запас. Ключ находится только в Python.

Для режима без кнопки `listener-worklet.js` собирает пакеты по 1024 отсчёта. `SpeechGate` локально отсеивает короткие импульсы, тишину и низкочастотный гул, использует порог относительно шума, предзапись 0,3 секунды и завершение после 0,85 секунды паузы. В SpeechKit отправляется законченный WAV, не постоянный поток. `isDirectedSpeech` проверяет русские признаки вопроса/обращения; после ответа принимает короткие реплики в течение минуты. Микрофон выключается на перерыве, при скрытии окна и завершении; эхо аватара не записывается. Это не идентификация ребёнка: речевой фон телевизора может пройти фильтр. Следующий шаг качества — специализированный нейросетевой VAD и потоковый STT с отменой/уточнением.

## 3. Подсказки — реализовано

`dialogue.py` хранит историю и этап в памяти сервера. Клиент передаёт вопрос, уровень и ID диалога. Попытки 0–2 получают инструкцию дать маленькую подсказку и вопрос без итогового ответа. С попытки 3 допускается полное решение. Ошибка или отмена до получения текста не увеличивает этап. «Новое задание» сбрасывает его.

```python
reply = tutor.answer(question, history, level, attempt=attempt)
# этапы 1–3: одна подсказка + наводящий вопрос;
# этап 4+: полное объяснение допустимо;
# правильная попытка: проверка и похвала конкретного шага.
```

Следующий шаг: структурированные ответы (`hint`, `question`, `correct`, `solution`) и проверка учебных сценариев. Пока соблюдение запрета готового ответа зависит от YandexGPT; модель может ошибиться.

## 4. Озвучивание и губы — базовая связка реализована

POST `/api/dialog` возвращает ID задания. GET `/api/dialog/<id>` сообщает `thinking`, `speaking`, `done`, `error` или `cancelled`, текст и `cues`. WAV доступен через защищённый `/api/dialog-audio/<id>`. POST `/api/dialog-cancel` останавливает синтез. Если XTTS недоступен, текст сохраняется с объяснением ошибки.

```python
# Один процесс, обусловленность родителя кэшируется по SHA-256 образца:
conditioning = model.get_conditioning_latents(audio_path=[str(reference)])
for chunk in model.inference_stream(text, 'ru', *conditioning,
                                     stream_chunk_size=20, enable_text_splitting=True):
    # WAV-фрагмент + timeline публикуются атомарно в stream.json.
    # Клиент начинает воспроизведение до конца генерации.
    pass
```

`voice_engine.py` сериализует запросы, прогревает установленную модель и автоматически использует Apple GPU (MPS), если он доступен. Извлечение признаков образца остаётся на CPU, синтез идёт на GPU; при неподдерживаемой операции до первого чанка включается CPU. `PARENTAI_VOICE_DEVICE=cpu` принудительно выбирает CPU. При отмене процесс завершается; после пяти минут простоя модель также освобождается. `/api/voice-warm` подготавливает образец, `/api/voice-release` освобождает процесс после занятия. `/api/dialog-audio/<id>?chunk=N` защищён токеном и отдаёт только опубликованный фрагмент. Web Audio размещает чанки последовательно по реальному времени, а позиции губ смещает на начало каждого чанка.

Для низкой задержки можно явно выбрать `voice=yandex`: SpeechKit TTS синтезирует обычный голос `alena` в LPCM 16 кГц, Python добавляет WAV-заголовок. Образец родителя не используется. Это отдельный платный облачный режим; при отказе доступа приложение сохраняет текст и показывает причину, без скрытой смены голоса.

Окна аудио — 40 мс; паузы исключаются из распределения букв. Б/П/М смыкают губы, О/У/Ё/Ю округляют, И/Ы/Е/Й растягивают. Амплитуда управляет челюстью. Ф/В ограничивают раскрытие челюсти. Добавленных зубов нет. Полость рта принадлежит полученной модели; дополнительные зубы, язык и условные геометрические детали не добавляются. Движения сглаживаются и привязаны к Web Audio clock. Напоминания используют только амплитуду.

Для качественного русского lip-sync следующий шаг — фонемизация текста, принудительное выравнивание с WAV на сервере ; blendshapes GLB уже используются. Текущий алгоритм не даёт точного совпадения каждого звука.

## 5. Анимация и телефон

Реализованы повороты, наклоны, лёгкие речевые кивки, моргание, плавное покачивание корпуса и `prefers-reduced-motion`. `AvatarMotion` хранит текущую позу и скорости, сглаживая изменения целей критически демпфированной пружиной. Начало речи в локальном `SpeechGate` сразу переключает цель внимания на ребёнка, не дожидаясь STT. Верхние ряды шеи следуют повороту головы с убывающим весом, воротник и плечи остаются на месте. Напоминания не перекрывают вопросы и речь. Рендер ограничен 30 кадрами/сек.

Голова уже вращается отдельно от плеч. Взгляд слегка меняется внутри области глаз на UV фотографии; рамка очков и веки остаются привязанными к лицу. Дальнейшие этапы: полноценный риг глаз, реакции на успех и случайные моргания. Затем мобильный клиент: камера/MediaPipe/Three.js на телефоне, Yandex и XTTS на защищённом сервере. В проверке на этом Mac прогрев занял 29,89 сек., первый чанк — 0,84 сек., короткий ответ полностью — 3,12–3,50 сек. Без STT/YandexGPT. CPU-режим заметно медленнее; результаты и ограничения записаны в README. Не открывать текущий localhost-сервер в интернет без HTTPS, авторизации, лимитов и разделения профилей. Мобильная упаковка пока не реализована.

## 6. Понятный интерфейс

Настройка разделена на образ, голос и подготовку занятия. Перед началом можно явно отключить автоматический микрофон. На экране ребёнка микрофон расположен над аватаром, состояние обновляется из реального получения потока и локального детектора; переключатель немедленно освобождает поток. Перерыв и завершение доступны в верхней панели, настройки голоса/класса и подробности облака вынесены в блок для родителя. Если предварительная проверка камеры не нашла лицо, поток освобождается, а занятие не открывается.
