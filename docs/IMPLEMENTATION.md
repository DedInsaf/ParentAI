# Решение и пошаговый план

## 1. Голова — первый приоритет

Выбран лёгкий фронтальный гибрид: сетка лица MediaPipe, подогнанная оболочка головы и изогнутые поверхности с фототекстурой для волос, ушей, шеи и верхней части туловища. Оболочка начинается на 36 вершинах овала лица и уходит к затылку.

Новый профиль v5 использует два фронтальных снимка: крупный кадр лица и портрет по грудь. Портрет задаёт единую проекцию через `positionsFor`; `bakePortraitFaceAtlas` переносит только детали лица из крупного кадра в координаты портрета. Боковые снимки больше не требуются. Старый формат v3/v4 остаётся читаемым.

`portrait-geometry.mjs` строит объёмную сетку шеи и туловища по 11 проверяемым точкам фотографии: макушка, края волос и ушей, шея у воротника, плечи и нижняя граница туловища. Проекция каждой вершины совпадает с её UV. Шея начинается под челюстью и продолжается в плечи без отдельного цилиндра и независимого масштабирования. Волосы и уши имеют изогнутую геометрию с фототекстурой. Относительная глубина остаётся оценкой: RGB-кадр и ручной контур не измеряют скрытую форму тела.

Интерфейс после захвата показывает фотографию с передвигаемыми точками и предпросмотр. Поддерживаются pointer events, выбор точки из списка, клавиатура и кнопки сдвига. Начальный контур не помечается измеренным. Пока изменения не сохранены, переход к занятию отключён. Сервер проверяет координаты, порядок границ и наличие обоих фронтальных кадров перед атомарной записью; отмена восстанавливает сохранённый профиль. Камера занимает весь экран во время двух снимков, инструкции звучат голосом, захват ждёт неподвижности 1,8 секунды и перепроверяет замороженный кадр. Фронтальный аватар ограничен небольшими поворотами головы; полный профиль больше не показывается.

## 2. Голосовой вопрос — реализовано

`web/app.js::voiceQuestion` записывает моно через AudioWorklet по кнопке, ограничивает вопрос 25 секундами и освобождает микрофон до облачного запроса.

```python
from speech import SpeechRecognizer
recognizer = SpeechRecognizer(api_key)
text = recognizer.recognize(wav_bytes)
```

`speech.py` проверяет WAV, уровень и длину, преобразует 8–96 кГц в 16 кГц и отправляет raw LPCM в SpeechKit v1. Лимит API — 30 секунд и 1 МБ; приложение оставляет запас. Ключ находится только в Python.

Для режима без кнопки `listener-worklet.js` собирает пакеты по 1024 отсчёта. `SpeechGate` локально отсеивает короткие импульсы, тишину и низкочастотный гул, использует порог относительно шума, предзапись 0,3 секунды и завершение после 0,85 секунды паузы. В SpeechKit отправляется законченный WAV, не постоянный поток. `isDirectedSpeech` проверяет русские признаки вопроса/обращения; после ответа принимает короткие реплики в течение минуты. Микрофон выключается на перерыве, при скрытии окна и завершении; эхо аватара не записывается. Это не идентификация ребёнка: речевой фон телевизора может пройти фильтр. Следующий шаг качества — специализированный нейросетевой VAD и потоковый STT с отменой/уточнением.

## 3. Подсказки — реализовано

`dialogue.py` хранит историю и этап в памяти сервера. Клиент передаёт вопрос, уровень и ID диалога. Попытки 0–2 получают инструкцию дать маленькую подсказку и вопрос без итогового ответа. С попытки 3 допускается полное решение. Ошибка или отмена до получения текста не увеличивает этап. «Новое задание» сбрасывает его.

```python
reply = tutor.answer(question, history, level, attempt=attempt)
# этапы 1–3: одна подсказка + наводящий вопрос;
# этап 4+: полное объяснение допустимо;
# правильная попытка: проверка и похвала конкретного шага.
```

Следующий шаг: структурированные ответы (`hint`, `question`, `correct`, `solution`) и проверка учебных сценариев. Пока соблюдение запрета готового ответа зависит от YandexGPT; модель может ошибиться.

## 4. Озвучивание и губы — базовая связка реализована

POST `/api/dialog` возвращает ID задания. GET `/api/dialog/<id>` сообщает `thinking`, `speaking`, `done`, `error` или `cancelled`, текст и `cues`. WAV доступен через защищённый `/api/dialog-audio/<id>`. POST `/api/dialog-cancel` останавливает синтез. Если XTTS недоступен, текст сохраняется с объяснением ошибки.

```python
# Один процесс, обусловленность родителя кэшируется по SHA-256 образца:

for chunk in model.inference_stream(text, 'ru', *conditioning,
                                     stream_chunk_size=20, enable_text_splitting=True):

    # Клиент начинает воспроизведение до конца генерации.

```

`voice_engine.py` сериализует запросы, прогревает установленную модель и автоматически использует Apple GPU (MPS), если он доступен. Извлечение признаков образца остаётся на CPU, синтез идёт на GPU; при неподдерживаемой операции до первого чанка включается CPU. `PARENTAI_VOICE_DEVICE=cpu` принудительно выбирает CPU. При отмене процесс завершается; после пяти минут простоя модель также освобождается. `/api/voice-warm` подготавливает образец, `/api/voice-release` освобождает процесс после занятия. `/api/dialog-audio/<id>?chunk=N` защищён токеном и отдаёт только опубликованный фрагмент. Web Audio размещает чанки последовательно по реальному времени, а позиции губ смещает на начало каждого чанка.

Для низкой задержки можно явно выбрать `voice=yandex`: SpeechKit TTS синтезирует обычный голос `alena` в LPCM 16 кГц, Python добавляет WAV-заголовок. Образец родителя не используется. Это отдельный платный облачный режим; при отказе доступа приложение сохраняет текст и показывает причину, без скрытой смены голоса.

Окна аудио — 40 мс; паузы исключаются из распределения букв. Б/П/М смыкают губы, О/У/Ё/Ю округляют, И/Ы/Е/Й растягивают. Амплитуда управляет челюстью. Ф/В ограничивают раскрытие челюсти; отдельные упрощённые зубы и язык появляются при открытом рте. Движения сглаживаются и привязаны к Web Audio clock. Напоминания используют только амплитуду.

Для качественного русского lip-sync следующий шаг — фонемизация текста, принудительное выравнивание с WAV на сервере и полноценные blendshapes GLB. Текущий алгоритм не даёт точного совпадения каждого звука.

## 5. Анимация и телефон

Реализованы повороты, наклоны, лёгкие речевые кивки, моргание и `prefers-reduced-motion` для головы. Напоминания не перекрывают вопросы и речь. Рендер ограничен 30 кадрами/сек.

Голова уже вращается отдельно от плеч. Дальнейшие этапы: реакции на возвращение ребёнка и успех, риг глаз и случайные моргания. Затем мобильный клиент: камера/MediaPipe/Three.js на телефоне, Yandex и XTTS на защищённом сервере. В проверке на этом Mac прогрев занял 29,89 сек., первый чанк — 0,84 сек., короткий ответ полностью — 3,12–3,50 сек. Без STT/YandexGPT. CPU-режим заметно медленнее; результаты и ограничения записаны в README. Не открывать текущий localhost-сервер в интернет без HTTPS, авторизации, лимитов и разделения профилей. Мобильная упаковка пока не реализована.
